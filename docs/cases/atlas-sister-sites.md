# Atlas 姊妹站 · 参考库界面骨架

## 来源与制作方式

本案例把 Web Atlas 与 Motion Atlas 的界面抽象为列表、详情、文档三页，用同一套 DOM 与布局切换两种品牌。卡片内容为中性虚构条目，画面由 CSS 渐变与几何形状生成。研究关注页面采用的设计机制。

配色、圆角、标志、字体、顶栏、侧栏、卡片与吸附逻辑取自 [Web Atlas 固定提交](https://github.com/MIBXR/web-atlas/tree/2541e56a21d5321717b9397c14ae09462d562ee4/site)和 [Motion Atlas 固定提交](https://github.com/MIBXR/motion-atlas/tree/80aac18cd2fcef4a97e53b1ef9227a223136ff60/site)。设计决策依据作者提供的任务说明与配色研究原件；合并说明见 [Web #50](https://github.com/MIBXR/web-atlas/pull/50)、[Web #51](https://github.com/MIBXR/web-atlas/pull/51)、[Web #52–55 的素材规则](https://github.com/MIBXR/web-atlas/pull/55)及 [Motion #33–39 中的共享骨架与过渡](https://github.com/MIBXR/motion-atlas/pull/36)。

制作从仓库案例模板建立独立 HTML，再把品牌值映射到 `data-brand` 与 `data-theme`。三页共享顶栏，hash 路由负责内容替换；配色与品牌切换只更新变量。默认收起的设计决策面板把每页机制连到本文相应章节。

## 设计机制

| 维度 | 机制与作用 |
| --- | --- |
| 配色 | 中性正文、品牌底色色相与五个强调角色分工；作品保持各自配色。 |
| 字体 | `Inter, "Segoe UI Variable", "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；等宽为 `"JetBrains Mono", "Cascadia Mono", Consolas, monospace`。界面使用 12／14／16／20／28px 阶梯，主标题使用 clamp。 |
| 骨架 | 68px 顶栏、228px 侧栏、18px 卡片间距；详情 2:1 双栏、32px 间距，文档正文最大 860px。 |
| 形状 | Web 4／7／10px 圆角；Motion 8／12／16px 与 999px 胶囊。品牌替换不改变内容层级。 |
| 状态 | 顶栏当前页实心、侧栏当前项柔和；导航悬停使用中性次级面，按钮悬停使用柔和主题底。 |
| 动效 | 卡片上移 3px、画面放大 1.025；主体过渡 140ms ease-out、顶栏快照固定。减少动态直接切换。 |
| 协调 | 列表负责判断，详情负责观看与取材，文档负责理解；相同动作沿用相同控件形态。 |

## 决策与尝试

<a id="skeleton"></a>
### 共享骨架与品牌层

**问题**：两站分别演化，顶栏、目录、列表密度、字体与详情操作的位置逐渐不同。同样的浏览动作需要重新学习。

**尝试**：先逐页并排调整，再把共享项列成详细表格。长版规范覆盖字号、控件、目录与每个断点，容易与现有章节重复；只统一配色又无法解决操作位置不一致。

**最终方案**：统一顶栏、页脚、侧栏、列表与详情的结构、缓存入口、字体、图标、控件和配色角色。品牌层保留主题色、标志、圆角、底色色相及卡片附加信息；Web 显示来源标签与比较入口，Motion 显示能量曲线。两站内容由各自仓库维护。CONTRIBUTING 的姊妹站说明只写“共享骨架、品牌差异、配色与卡片”三段，细节归现有章节与代码，不增加检查脚本。

**数值**：顶栏 68px；左右 32px，801–1159px 为 24px，800px 及以下为 16px；侧栏 228px。Web `--r-sm/--r/--r-lg` 为 4／7／10px，Motion 为 8／12／16px，顶栏当前项另用 `--r-pill:999px`。共享控件高 44px，功能图标 16px、线宽 1.8。

<a id="surfaces"></a>
### 底色与卡片

**问题**：Web 的浅色卡片与底色同偏绿，深色侧栏成为全页最重区域；深色模式大面积绿黑也使内容显得沉闷。Motion 的暖白底与暖白卡片缺少清楚的层次。

**尝试**：[底色与卡片研究原件](../../demos/cases/atlas-sister-sites/source/index.html)把白、黑、灰三种作品放入相同画面。Web 浅色 A 是偏绿底＋偏绿卡片＋深色侧栏，B 改白卡片但保留深侧栏，C 改浅侧栏，D 反转为中性底＋偏绿卡片。Web 深色 A 为绿底绿卡片，B 为中性底绿卡片，C 为中性底中性卡片，D 为绿底中性卡片。Motion 浅色比较 A 暖底暖卡与 B 暖底白卡；深色比较 A 中性底中性卡与 B 中性底微暖卡，原件各两案。

**最终方案**：Web 浅色取 C 的关系，实际侧栏与卡片统一白色；深色取 B。Motion 两种主题都取 B；浅色底随后从 `#f1eee7` 收敛为 `#f6f4ef`。深色侧栏方案被舍弃，因为其重量压过作品，也使浅色页面出现一个独立深色系统。浅色让底色带品牌倾向、内容面正白；深色让大底接近中性，品牌色留在抬升的表面。

| 品牌与主题 | 页面底 | 卡片／侧栏 | 内层次级面 | 正文／次要文字 | 页面线／表面线 |
| --- | --- | --- | --- | --- | --- |
| Web 浅 | `#f4f5ee` | `#ffffff` | `#f4f5ee` | `#252822`／`#62695b` | `#dcded4`／`#dfe1d7` |
| Web 深 | `#121313` | `#1c201b` | `#252b23` | `#edf0e6`／`#b3b8ad` | `#2c2f2b`／`#343b31` |
| Motion 浅 | `#f6f4ef` | `#ffffff` | `#f6f4ef` | `#17181b`／`#6a6862` | `#d9d3c6`／`#c3bcad` |
| Motion 深 | `#0c0d0f` | `#1a1816` | `#221f1c` | `#ecebe6`／`#8f8d87` | `#2a2d33`／`#3b3f46` |

**数值**：卡片圆角使用各站 `--r-lg`，内边距至少 16px；内层使用 `--surface-2` 与 `--r`，离外缘至少 12px。列表内层预览带 1px 边框，卡片网格 `repeat(auto-fill,minmax(300px,1fr))`、间距 18px。Motion 固定提交使用 `--line-2` 作为内层控件边界，上表按该实际值记录。

<a id="accent-tiers"></a>
### 主题色分层

**问题**：一枚明亮主题色同时当正文链接、眉题、按钮底和高亮条时，各背景上的对比不同。把所有操作都涂成品牌色，又会让动作与数据争抢注意。

**尝试**：第一轮把“通用操作控件中性”扩大成“主题色只留给当前项与复制按钮”，正文链接、时间码、进度、能量曲线与提示块一起失去色彩。恢复这些内容角色后，用[主题色层级原件](../../demos/cases/atlas-sister-sites/source/accent-tiers.html)逐项比较。原件先合并实心底与高亮条，深色标题因此需要单独拆出高亮色。

**最终方案**：五层是深色强调、强调文字、实心底、高亮条、柔和底。实心底配独立的 `--accent-3-ink`；焦点用 `--accent-1`，按钮悬停用 `--accent-4` 底和 `--accent-1` 文字与边框。播放、视图、收藏、下载等通用控件的常态保持中性。恢复的主题色用于链接、眉题、当前项、提示及数据可视化。

| 角色／变量 | 用途 | Web 浅 | Web 深 | Motion 浅 | Motion 深 |
| --- | --- | --- | --- | --- | --- |
| 深色强调 `--accent-1` | 正文链接、焦点、进度与下划线 | `#4b6118` | `#d4ef76` | `#b8330f` | `#ff7a52` |
| 强调文字 `--accent-2` | 眉题、编号、侧栏当前项文字 | `#5f7a1f` | `#bcd86a` | `#d0401a` | `#ff6a3f` |
| 实心底 `--accent-3` | 顶栏当前页、复制 Prompt | `#d4ef76` | `#d4ef76` | `#ef4d24` | `#ff5b2e` |
| 实心字 `--accent-3-ink` | 实心底承托的文字 | `#252822` | `#252822` | `#ffffff` | `#160804` |
| 高亮条 `--accent-mark` | 标题下方的短色带 | `#d4ef76` | `#526438` | `rgba(239,77,36,.35)` | `#8a2c14` |
| 柔和底 `--accent-4` | 侧栏当前项与提示 | `#eef6d2` | `#2a3320` | `#fbe4dc` | `#3a1d14` |

Web 深色高亮条取 `#526438`，浅色标题 `#edf0e6` 对其为 5.62；它与实心按钮的亮绿职责不同。品牌标志和装饰图形维持独立颜色，不放进五层：Web 标志为浅 `#657d2b`／深 `#d4ef76`。Motion 在删除旧主题变量时，SVG 仍引用被删变量，图形回落成黑色；最终改为 `--brand-mark`，浅 `#df3f17`、深 `#ff5b2e`，与标签栏图标对应。

<a id="emphasis"></a>
### 当前项与悬停

**问题**：顶栏与侧栏承担不同层级，但同样的实心色块让它们一样重。把悬停也涂成柔和主题色，则临时经过的位置看起来像另一个当前项。

**尝试**：[当前项对照原件](../../demos/cases/atlas-sister-sites/source/emphasis.html)列出 A 全实心、B 顶栏实心＋侧栏柔和、C 全柔和。A 的侧栏争抢注意；C 削弱了全站位置。选 B 后，导航悬停一度使用 `--accent-4`，再依据 [Web #51](https://github.com/MIBXR/web-atlas/pull/51)改回中性。

**最终方案**：顶栏与手机“全站导航”当前项实心；侧栏、手机“本页目录”和本文目录当前项使用柔和底、强调文字与 650 字重。非当前导航悬停为次级面＋正文色，不加主题色描边。当前项悬停保持当前样式。卡片与正文链接悬停保留其各自反馈，按钮继续用主题色柔和反馈。

**数值**：实心使用 `--accent-3/--accent-3-ink`；柔和使用 `--accent-4/--accent-2`。卡片只上移 3px、加阴影、预览放大 1.025，卡片底色不变。收藏星的方框 28×28px，与标题第一行对齐；顶栏当前项高 36px。

<a id="sticky"></a>
### 两栏吸附

**问题**：长说明滚动时舞台离开视口，观看与阅读分离；把两栏各自做成滚动容器，又会制造两个滚动条。

**尝试**：第一版按短栏高度选择 top：能放进视口就贴操作栏下，放不进则取“视口高－栏高－下留白”，产生负 top。这个算法让舞台先上移、再按底部停住，违背舞台始终可见的目标，因此被撤回。

**最终方案**：照 [Web detail-layout.js](https://github.com/MIBXR/web-atlas/blob/2541e56a21d5321717b9397c14ae09462d562ee4/site/shared/detail-layout.js)读取操作栏、舞台与说明高度。舞台列始终 sticky；舞台比说明长时，说明栏也 sticky。两栏共用一个网格与页面滚动条，`align-items:start`；容器末尾按 sticky 的自然约束让底边对齐后一起离开。ResizeObserver 观察顶栏、操作栏与两栏，resize 重新计算。

**数值**：两栏 `minmax(0,2fr) minmax(340px,1fr)`、32px 间距；top 为 68px 顶栏＋操作栏实高＋24px。1160px 起吸附，1159px 及以下单列。两栏及最后子元素下边距为 0，内容末尾 48px 后接页脚。Demo 用 8／2 节说明演示右栏较长／较短两种分支；手机视图改变舞台画面宽度，滚动容器保持不变。

<a id="docs-reader"></a>
### 文档中心

**问题**：查找一篇文档与定位其内部章节是两件事。把两种目录都做成卡片或多层导航，会挤压阅读区域；长标题换行还使左栏每行高度失去节奏。

**尝试**：左栏使用更宽目录和分组套卡片，右侧本文目录也套独立框体。扁平化后吸顶背景一度透明，下方文字穿过搜索框；Motion 的单行高亮还溢出卡片右边。

**最终方案**：左栏一张卡片，标题单行省略并用 title 保存全文；搜索与分组标题吸顶，背景为不透明侧栏表面，底部 8px 渐隐遮住滚动内容。分组顺序为项目指南、研究、素材使用、Prompt、项目说明；初始展开当前文档分类，切换保留手动开合与滚动，只展开新目标分类。正文直接落在页面底色上；右侧本文目录为贴右纯列表、滚动同步当前节。仓库内所有 Markdown 链接通过阅读器打开，包含锚点及目录之外的文件。

**数值**：桌面 `228px minmax(0,1fr) 228px`，间距 32px；正文最大 860px、标题最大 44px、正文 16px。手机把全站文档目录收入顶栏菜单，本文目录用右下角浮动按钮打开，两者互斥。Demo 的表格和代码块按本案例要求用次级面与 `--r`；线上阅读器的白表面与 `--r-lg` 见复现范围。

<a id="transitions"></a>
### 页面切换

**问题**：导航更换整页时，顶栏和主体一起淡化，会削弱持续存在的位置感。只配置跨文档过渡也覆盖不到同一 HTML 内的 hash 路由。

**尝试**：先给两站跨页加入 `@view-transition { navigation:auto }`，再把列表／详情、详情／详情和文档切换的 DOM 更新包进 `document.startViewTransition`。Motion 首帧需要等共享顶栏生成，才能把它纳入独立快照。

**最终方案**：顶栏命名为 `atlas-header`，该组与新快照无动画、旧快照隐藏，主体根过渡保留。浏览器不支持或系统减少动态时直接更新 DOM。Demo 的三个页面使用同一 HTML，因此演示页内过渡。

**数值与排查结论**：根过渡 140ms、ease-out。维护者记录 Edge 偶发 `ViewTransition opt-in disabled`，可发生于任意页面，频率约 1/4；没有可见影响，保留原状。该记录与减少动态时主动绕开过渡是两种状态。

<a id="capacity"></a>
### 规则变更的代价

**问题**：给已有舞台补上统一卡片圆角、边框与内边距，会压缩其内部可用高度。外观规则改变了滚动叙事的容量条件。

**尝试与事故**：卡片规则使 Web 首页叙事窗口由约 557px 降为 480px，嵌入实验室的内容放不下；原有溢出保护把滚动叙事退回平铺。只调整外框视觉无法恢复滚动形态。

**最终方案**：保留公共卡片表达，同时恢复叙事窗口内部及嵌入实验室的原容量。布局判断继续依据实际可用空间，不新增另一套保护机制。

**数值**：[Web #50 的恢复记录](https://github.com/MIBXR/web-atlas/pull/50)在 1440×900 下为窗口 558px、嵌入实验室 417px；基线分别为 557／415px。这个案例说明内边距要与容器的真实内容容量一起决定。

<a id="favicon"></a>
### 标签栏图标

**问题**：站内主题可以与浏览器主题不同，网页中的主题按钮无法改变浏览器标签栏的底色。按站内主题换 favicon，会让图标选错承托背景。

**尝试**：用脚本跟随站内主题切换图标路径；这把网页显示偏好与浏览器标签栏混为一谈。

**最终方案**：单个 favicon.svg 内通过 `prefers-color-scheme` 选择颜色，直接跟随浏览器环境。删去站内换图标脚本。两站使用各自原始品牌路径，颜色独立于内容角色。

**数值**：Web 为 `#657d2b`／`#d4ef76`，Motion 为 `#df3f17`／`#ff5b2e`，图标 viewBox 都是 96×96。以各站浅／深页面底作同色对照参照，Web 为 4.23／14.54，Motion 为 3.93／6.28；标签栏背景由浏览器决定。这些值描述颜色关系。

<a id="hosting"></a>
### 素材托管

**问题**：大图、音视频与制作依赖使发布包膨胀；原文快照一度被豁免，快照里的素材随站点完整上传。

**尝试**：快照大素材改成固定 GitHub 地址后，曾用 `_redirects` 保留原路径；Sites 把该文件作为普通文件返回。经入口代理素材的尝试也被撤回。

**最终方案**：[Web #54](https://github.com/MIBXR/web-atlas/pull/54)与 [Motion #38](https://github.com/MIBXR/motion-atlas/pull/38)复用既有素材解析器：发布副本改写 HTML／CSS，文档素材链接直接指向固定提交原件，仓库原件与 Markdown、许可保持原样。快照和普通素材使用同一规则。两站扩展名及扫描范围对齐，覆盖发布包全部目录。

**数值**：阈值为至少 128 KiB，固定完整 Git 提交；覆盖图像、音视频、字体及 `.glb/.gltf/.bin/.blend/.hdr/.ply` 等制作文件。Motion #39 把约 31MB 的 Blender 工程、环境光和网格移出发布包；Web #55 同步扩展名和范围。当前案例的三份研究 HTML 随源码保存，独立 Demo 无外部图像请求。

## 怎么修改

`app.js` 的 `cases` 保存虚构条目的标题、分类、摘要、标签与图版配色；`noteSections` 和 `docsPage()` 保存详情说明与示例文章。`style.css` 开头四组选择器保存品牌及主题变量，后续布局段分别对应三页。吸附在 `detailPage()` 的 `syncColumns`，页面过渡在 `transition()`。
